# هدف

این سند قوانین کسب‌وکار پروژه را تعریف می‌کند.

هیچ کدی نباید قانونی را پیاده‌سازی کند که در این سند وجود ندارد.

در صورت تضاد بین Database و Business Rules،
همیشه Business Rules معتبر است.

============================================================

# BR-001
یک Customer می‌تواند در آینده نقش‌های مختلف داشته باشد.

نسخه اول:

فقط نقش Project Member فعال است.

============================================================

# BR-002

هر Customer دارای یک شماره مشتری (customer_no) یکتا است.

شماره مشتری تغییر نمی‌کند.

============================================================

# BR-003

هر Project دارای یک project_code یکتا است.

این کد پس از ایجاد تغییر نمی‌کند.

============================================================

# BR-004

رابطه عضویت بین Customer و Project توسط ProjectMember مدیریت می‌شود.

بنابراین Customer مستقیماً عضو پروژه نیست.

============================================================

# BR-005

هر ProjectMember فقط یک قرارداد عضویت فعال دارد.

============================================================

# BR-006

بعد از انتخاب واحد،

یک Final Contract ایجاد می‌شود.

============================================================

# BR-007

هر Unit فقط به یک Project تعلق دارد.

============================================================

# BR-008

هر Unit در هر لحظه فقط یک مالک فعال دارد.

============================================================

# BR-009

تغییر مالکیت مستقیم مجاز نیست.

مالکیت جدید فقط با قرارداد جدید ثبت می‌شود.

============================================================

# BR-010

هر Project فقط یک Financial Plan فعال دارد.

============================================================

# BR-011

Financial Plan نسخه‌دار است.

در صورت تغییر،

نسخه جدید ایجاد می‌شود.

نسخه‌های قبلی حذف نمی‌شوند.

============================================================

# BR-012

تمام رویدادهای مالی در FinancialTransaction ثبت می‌شوند.

هیچ جدول مالی موازی ایجاد نمی‌شود.

============================================================

# BR-013

FinancialTransaction حذف نمی‌شود.

در صورت اشتباه،

Reverse Transaction ثبت می‌شود.

============================================================

# BR-014

هر FinancialTransaction دقیقاً یک نوع (TransactionType) دارد.

نمونه:

PROJECT_PLAN

MEMBER_PAYMENT

LOAN

SUBSIDY

DISCOUNT

UNIT_DIFFERENCE

BANK_TRANSFER

CHEQUE

MANUAL_ADJUSTMENT

============================================================

# BR-015

هر FinancialTransaction اثر مشخصی دارد.

DEBIT

یا

CREDIT

============================================================

# BR-016

تمام FinancialTransaction ها در نهایت به JournalEntry متصل می‌شوند.

============================================================

# BR-017

هر JournalEntry حداقل دو JournalLine دارد.

قانون حسابداری دوبل الزامی است.

============================================================

# BR-018

جمع بدهکار و بستانکار سند همیشه برابر است.

============================================================

# BR-019

JournalEntry در وضعیت Posted قابل ویرایش یا حذف نیست.

============================================================

# BR-020

اصلاح اسناد فقط با سند اصلاحی انجام می‌شود.

============================================================

# BR-021

تمام عملیات مهم دارای AuditLog هستند.

============================================================

# BR-022

Hard Delete برای اطلاعات مالی ممنوع است.

============================================================

# BR-023

تمام Import ها در یک Transaction دیتابیس انجام می‌شوند.

در صورت خطا،

Rollback کامل انجام می‌شود.

============================================================

# BR-024

صورتحساب بانکی فقط برای مغایرت‌گیری است.

ثبت فیش وابسته به صورتحساب نیست.

============================================================

# BR-025

مانده هر حساب از روی گردش‌ها محاسبه می‌شود.

هیچ مانده‌ای به صورت دستی ذخیره نمی‌شود،

به جز Snapshot های کنترلی.

============================================================

# BR-026

Snapshot مانده بانک توسط کاربر مالی یا Import ثبت می‌شود.

============================================================

# BR-027

در صورت اختلاف بین Snapshot و مانده محاسباتی،

وضعیت حساب "دارای مغایرت" می‌شود.

============================================================

# BR-028

همه گزارش‌ها فقط خواندنی هستند.

============================================================

# BR-029

Business ID ها قابل تغییر نیستند.

============================================================

# BR-030

Database ID ها هرگز در رابط کاربری نمایش داده نمی‌شوند.

============================================================

# BR-031

Repository مرجع رسمی پروژه است.

============================================================

# BR-032

هیچ AI یا توسعه‌دهنده‌ای مجاز به تغییر معماری بدون ثبت ADR جدید نیست.
